>大范围上的答案，是否等于，左部分答案+右部分答案+跨越两边的答案

>把n^ 2复杂度变成nlogn

>思考如果**左右分别有序**的话是否会产生便利性（有序之后这个比较有点像merge，左右都是不走回头路。。因为比如左边到了一个位置之后右边再往后走这个位置一定是成立的（这个是==**有序==赋予的条件**））

>既返回范围内最小和，又要排好序

>这里面用这个方法每次递归出来的的答案都不是这个数字“对应”的答案，而是这个范围内部存在的答案
>但是**推窗**的时候确实是判断这两个数字怎么怎么样
## 小和问题
可以想成只要左边比右边小就可以被加进去
```cpp
int smallsum(int l,int r){
	%% basecase没有小和 %%
	if(l==r){
		return 0;
	}
	int m = (r+l)/2;
	return smallsum(l,m)+smallsum(m+1,r)+merge(l,m,r);
}
%% 要注意，这种递归最小的一层就是basecase，直接return %%

%% 后面的merge函数可以看成 1.固定不变的**要有排序的功能** 2.其他功能根据题意放在前面%%
%% 放在前面是因为你排序是整体排序可能会影响正常的结果（破坏了左右原有的分别有序），所以需要先把正事干了 %%
int merge(int l,int m,int r){
	int ans = 0;
	for(int i = l,j = m+1,sum = 0;j<=r;j++){
		%% 算sum %%
		while(i<=m && arr[i]<=arr[j]){
			sum+=arr[i++];
		}
		ans+=sum;
	}
	int a = l,b = m+1,k = l;
	while(a<=m&&b<=r){
		help[k++] = arr[a]<=arr[b] ? arr[a++] : arr[b++];
	}
	while(a<=m){
		help[k++] = arr[a++];
	}
	while(b<=r){
		help[k++] = arr[b++];
	}
	for(k = l;k<=r;k++){
		arr[k] = help[k];
	}
	return ans;
}
```
复杂度的乘法关系要求内层每轮**独立重新执行**。这里 i 是全局单向推进的，内层 while 的总执行次数被左半长度上界严格卡死，和外层 j 没有乘法关系——所以是**O(n)**

把int换成long,,要注意溢出问题

**每次要merge的时候无论归并排序还是归并分治两侧都是分别有序的**
每个半边的和都等于半边内部两个半边的和加上跨越的和。最小的那个情况没有半边了只有跨越
## 反转对数量问题
```cpp
int num(int l,int r){
	m = (l+r)/2;
	%% basecase %%
	if(l==r){
		return 0;
	}
	return num(l,m)+num(m+1,r)+merge(l,m,r);
}
int merge(int l,int m,int r){
	int ans = 0
	for(int i = l,j = m+1,sum = 0;i<=m;i++){
		while(j<=r&&arr[i]>2*arr[j]){
			sum+=1;
			j++;
		}
		ans+=sum;
	}
	%% 这里也可以用j直接 %%
	int a = l,b = m+1,k = l;
	while(a<=m&&b<=r){
		help[k++] = arr[a]<=arr[b] ? arr[a++] : arr[b++];
	}
	while(a<=m){
		help[k++] = arr[a++];
	}
	while(b<=r){
		help[k++] = arr[b++];
	}
	for(k = l;k<=r;k++){
		arr[k] = help[k];
	}
	return ans;
}
```
